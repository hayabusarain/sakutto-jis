# サクッとJIS 運営戦略

最終更新: 2026年10月3日

このサイトを「失敗させない」ための計画です。5つの観点（収益、法務、検索、使う人の価値、続けやすさ）から「1年後に失敗しているとしたら原因は何か」を洗い出し、別の視点で見直したうえで、対策・成長計画・運用ルール・撤退の基準にまとめました。

検索数・広告単価・競合の順位は、調べた範囲からの推定です。確かめていない点には（推定）と書いています。

---

## 1. 目標と勝ち筋

**誰のためのサイトか**
- 保全・配管・機械設計の現場で、スマホで寸法を確かめたい人
- 図面を描く前に、規格の値と計算の根拠を確かめたい設計者

**勝ち筋**
- 表を写しただけのサイトにはしない。**計算する・見分ける・拾い出す・DXFで出す・印刷して貼る**ための道具になる。
  - 「SGP 寸法表」のように表を見れば済む検索は、メーカー・老舗サイト・検索結果に出る AI の要約が強い。ここで勝負しない。
- **値の信頼性を見える形にする。** 規格の原文と全数照合し、結果の横に表番号を出す。誤記報告を受けて直し、その記録も公開する。
- **現場の困りごとに一言添える。** 例：「M12 の下穴は 10.2 か 10.3 か」「旧JISのスパナは19」。

**1年後の目標（推定に基づく目安）**
- 検索からのクリック：月 3,000〜1万
- 誤記報告への対応：届いてから1週間以内（これは必ず守る）
- 収益：広告で月数千円。お金よりも「使われていること」を優先する

## 2. 失敗シナリオと対策

| 順位 | 失敗の理由 | 対策 | 状態 |
|---|---|---|---|
| 1 | 検索で見つからない（新しいドメイン・被リンクなし・AI要約に取られる） | 計算・判別の検索語を狙う（4章）。現場メモ記事、印刷用早見表、拾い出しツールで「ここにしか無い」ものを作る | 実装済み（記事は月1本ずつ追加） |
| 2 | 「（仮）」のまま公開できずに終わる | 運営者情報・連絡先・ドメインを今週決める（3章）。本番ビルドでは仮の値を残せない仕組みを入れた | 仕組みは実装済み／運営者の作業待ち |
| 3 | AdSense 停止がゲーム攻略サイトに及ぶ | 同じアカウントなら、自動広告はオフ・手動2枠まで（5章）。同じ職場の人に広告を押さないよう頼む | 方針のみ |
| 4 | 勤務先とトラブルになる | 就業規則で副業の扱いを確認する。写真は私物・市販品だけにし、銘板や顧客の設備は写さない | 運営者の作業 |
| 5 | 値の誤りで事故・悪評につながる | 規格原文と全数照合済み（2026-10-03）。誤記報告ボタン、更新履歴、緊急停止の仕組みを用意した | 実装済み（G 3452・G 3454 の2026年版だけ未照合） |
| 6 | 一度使われて終わる | 現場の一言、QR付きの早見表、条件付きのURLで LINE 共有、オフライン対応 | 実装済み |
| 7 | 広告が見られない・押されない | 広告に頼りすぎない。結果の後・ページの最後にだけ置く | 方針のみ |
| 8 | 続かない（本業の繁忙期・反応がない） | 月8時間まで。誤記対応を最優先にする。CIで壊れた版を出さない。アクセス解析で反応を見る | 仕組みは実装済み |
| 9 | 著作権・リポジトリが公開のまま | 規格の文章・図は載せず、値と自前の計算・表の組み方で構成する。サイトが非公式であることを明記した。GitHub のリポジトリを非公開にする | 一部実装済み／リポジトリは運営者の作業 |
| 10 | AdSense の審査に落ちる | 記事と独自の道具を増やし、Search Console で表示が出始めてから申請する。審査はサイトごとなので、落ちてもアカウントには影響しない | 方針のみ |

**この中で特に損失が大きいもの（起こる確率は低いが、起きると取り返しがつかない）**
- 値の誤りによる事故
- AdSense アカウントの停止
- 勤務先とのトラブル

どれも、公開前の確認でほぼ防げます。

## 3. 公開までにやること（運営者の作業）

コードの準備は済んでいます。あとは次の作業です。

1. **リポジトリを非公開にする**（任意・おすすめ）：GitHub のリポジトリの Settings → General → Danger Zone → Change visibility。Cloudflare からの公開には影響しません。
2. **ドメインを取る**：Cloudflare Registrar などで取得。会社のフィルタは、登録して間もないドメインを止めることがあります（推定）。早めに取っておくと安心です。
3. **連絡先を作る**：サイト専用の Gmail と、誤記報告用の Google フォームを用意する。
   - フォームには「ページのURL」を入れる記述式の質問を作る。「事前入力したURLを取得」で `entry.○○` を調べて、`src/site.ts` の `REPORT_PAGE_FIELD` に書く。こうすると、報告ボタンからページのURLが自動で入ります。
4. **`src/site.ts` を書き換える**：運営者名、メール、`REPORT_URL`、`REPORT_PAGE_FIELD`。経歴（`profile`）は、書かないなら空文字にする。
5. **就業規則と AdSense アカウントの扱いを確認する**（2章の3・4位）。
6. **Cloudflare に公開する**（README の手順）。本番の環境変数は次のとおり。
   - `VITE_SITE_URL` = `https://（ドメイン）`
   - `REQUIRE_SITE_CONFIG` = `1`（仮の値が残っているとビルドが止まり、公開されない）
   - `VITE_GA_ID` = GA4 の測定ID（アクセス解析を使う場合）
7. **スマホで一通り触る**：主要ツール、検索、印刷用早見表、オフライン表示を確かめる。

## 4. 公開後の成長計画

### 公開してすぐ（1か月）
- Google Search Console と Bing Webmaster Tools に登録し、サイトマップ（`/sitemap.xml`）を送る。
- GA4 の拡張計測機能で、**「ブラウザの履歴イベントに基づくページの変更」をオフにする**。ツールは入力のたびにURLを書き換えるので、オンのままだとページビューが水増しされる。
- 計測するもの（実装済み）：ページ表示、結果のコピー、表のコピー・CSV、DXF、共有、印刷。
- 知り合いの現場の人に使ってもらい、「迷ったところ」を3つ集める。

### 3か月
- **現場メモを増やす。** 月1本のペース。Search Console の「表示はされるがクリックされない検索語」から題材を選ぶ。
- **印刷用早見表を配る。** QRコード付きなので、現場の壁や工具箱に貼ってもらう。
- **ガスケット寸法（JIS B 2404）を追加する。** 原文と照合してから載せる。拾い出しツールでガスケットの寸法まで出せるようになる。
- **G 3452・G 3454 の2026年版の表と照合する。** 原文が読めるようになったら確認し、年版の表示を更新する。

### 1年
- 規格改正の解説記事（例：G 3452:2026 で何が変わったか）
- 自分の現場の基準（ガスケット厚さ・ナットの種類など）を保存できる「マイ設定」
- SUS管（JIS G 3459）の寸法：照合する表が大きいので、手間を見て判断する

### 後回しにするもの
締付けトルクと耐圧試験の計算は後回しです。事故に直結し、前提条件（摩擦係数・材料・ガスケット）の説明も難しいからです。

### 見る数字（KPI）

| 時期 | 見る数字 | 目安（推定） |
|---|---|---|
| 1か月 | Search Console の表示回数 | 0 からの立ち上がりを確認 |
| 3か月 | 検索からのクリック | 月300以上 |
| 6か月 | 検索からのクリック・コピー／DXF／印刷の回数 | 月1,000以上 |
| 12か月 | 検索からのクリック | 月3,000〜1万 |

## 5. 収益化の方針

- **AdSense は焦らない。** 現場メモ数本と独自ツールがそろい、Search Console で表示が出始めてから申請する。
- **広告の置き場所は2か所まで。** 結果カードの後と、ページの最後。条件の入力欄と結果の間には置かない（誤タップの防止）。広告枠の部品は用意済み（`src/components/ui/AdSlot.tsx`。環境変数と広告ユニットIDが無ければ何も出ない）。
- **自動広告を使うなら**、上部のアンカー広告はオフにする（画面上部のツール切替バーと重なる）。
- **ゲーム攻略サイトと同じアカウントの場合**、職場の同僚によるクリックは不正扱いされるおそれがある。アクセスが増えるまで広告なしで始めるのも手。
- **広告以外**：Amazon アソシエイト（工具・ノギスなど）は月数百円の見込み。当面は、スポンサーや有料のDXF販売に手を広げない。

**収益の見通し（推定）**：広告2枠、1,000PVあたり150〜400円として計算。

| シナリオ | 12か月後のPV/月 | 広告収入/月 |
|---|---|---|
| 悲観 | 1,000〜3,000 | 150〜1,000円 |
| 標準 | 5,000〜1.5万 | 750〜6,000円 |
| 楽観 | 3万〜6万 | 4,500〜2.4万円 |

規格を買いそろえる費用（数万円）は、1年目の収入を上回ることがあります。お金を失うリスクより、時間を使うことのほうが大きいと考えてください。

## 6. 品質と信頼の守り方

- **データの照合**：規格票の原文と全数照合済みです（2026-10-03、`docs/data-verification.md`）。結果の横に表番号を出しています。
- **規格改正のウォッチ**：年1回、JSA Webdesk で使っている規格の「状態」と「確認日」を確かめる。対象は `src/standards.ts` の一覧。
  - すでに起きている改正：JIS G 3452・G 3454 は 2026-05-20 に改正。サイトは2019年版で照合した値で、その旨を画面に出している。
- **誤記対応**：報告が届いたら1週間以内に原文で確かめ、直したら `src/site.ts` の `SITE_CHANGELOG` に記録する（編集方針のページに表示される）。
- **確認できない値の扱い**：載せないか、`UNVERIFIED` に入れて画面に ※ を付ける（仕組みは残してある）。
- **緊急停止**：古い・壊れた版が端末に残って困るときは、`SW_KILL=1` でビルドして公開すると、端末のキャッシュを消して解除できる。直ったら通常のビルドに戻す。
- **壊れた版を出さない**：GitHub Actions がプッシュのたびに型・コード・テスト・ビルドを確かめる（`.github/workflows/ci.yml`）。

## 7. 運用のルーチン（月8時間まで）

| 頻度 | やること |
|---|---|
| 毎週（10分） | 誤記報告フォームの確認。GitHub の CI が赤くなっていないか |
| 毎月（2〜3時間） | Search Console で伸びている検索語・落ちている検索語を見る。現場メモを1本。依存パッケージの更新（`npm outdated`）とビルドの確認 |
| 3か月ごと | GA4 で、よく使われる機能と使われない機能を見る。使われない機能は縮める |
| 毎年 | 規格の改正を確認（6章）。ドメインの更新、AdSense・Cloudflare のアカウント状態の確認 |

本業の繁忙期（定期修理の時期など）は、誤記対応だけにします。

## 8. 撤退・方針転換の基準

- 公開から **180日たっても検索からのクリックが月300に届かない** → 広告をやめ、「自分と仲間の道具」として静かに続ける（費用はドメイン代だけ）。
- **誤記対応が1か月以上できない状態が続く** → 該当のツールに「更新停止中」の注記を出す。
- **規格団体などから指摘を受けた** → 該当箇所をすぐ公開停止にしてから相談する。

## 10. 前提にしている推定（確かめていないこと）

- 狙う検索語の検索数（合計で月1万〜3万回）と広告単価（1,000PVあたり150〜400円）
- 競合の順位。調べた範囲では、2026年に似た計算ツールが出ている（ryubi.co.jp のフランジボルト計算、haikann の「フランジボルトナビ」）
- 会社のフィルタが、新しいドメインを止める期間
- iPhone の Safari で、しばらく開かないとサイトの保存データが消える仕組みの影響（入力の保存とオフラインのキャッシュ）
